# V1.5 —— 语音与电话模式

> 版本：V1.5　状态：语音链路三档 ASR + TTS + 免手电话模式（连续多轮 + 音波 UI）已交付、真机验证。
> 本文是 V1.5 语音子系统的权威说明：能力、架构、限制、配置。设计依据见
> `docs/鸿蒙智能体平台系统设计.md` §15–§18。

---

## 1. 一句话

在鸿蒙上给本地/远程模型**打电话**：按住说话转文字、助手回答逐句朗读、免手连续多轮对话，
语音全链路**分层降级**（系统 → 远程 → 离线），断网也能语音输入。

## 2. 交付能力

| 能力 | 说明 | 档位 |
|---|---|---|
| **按住说话** | 输入区麦克风按住即录、松手转文字追加进草稿 | 系统/远程/离线 ASR |
| **消息朗读** | 助手消息点「朗读」出声，可停 | 系统/远程/离线 TTS |
| **免手电话模式** | 听筒进入：自动聆听→识别→走正常聊天链路（绑定智能体/记忆/工具、入会话流）→逐句朗读→**连续多轮**直到挂断 | 全链路 |
| **音波 UI** | 电话模式以**呼吸律动的音波球**表达状态（聆听/思考/说话各有律动与配色），当前轮文字小字辅显（ChatGPT 式） | — |
| **打断** | 说话中「打断说话」按钮插话；远程档回声消除可用时外放可**声控打断**；戴耳机可开声控插话 | — |

**分层降级**（对上层透明，`SpeechService` 门面自动选档）：
- **ASR**：`优先离线?离线 : 远程(配了)→系统→离线(兜底)`
- **TTS**：`远程(配了)→系统`；离线 TTS 为**实验开关**（默认不用，见 §5）

## 4. 回声与打断（电话模式的核心设计）

**问题**：外放时麦克风会收到助手自己的 TTS，被识别成"用户说的话" → 自问自答。VAD 救不了
（TTS 输出本身就是语音）。唯一出路是**声学回声消除（AEC）**，而 AEC 需要"正在播什么"的**参考信号**。

**本机实测结论（华为平板 / 手机）**：
- **系统 TTS 不吐 PCM**（`onData` 在本机六组参数都不触发），也不在通话音频路径 → 消不了回声。
- 故**外放 + 系统 TTS = 半双工**：助手朗读时不开麦，说完自动轮到你；朗读中用**按钮**打断。
  （对齐 HuggingFace speech-to-speech 的本地麦做法：`should_listen.clear()` 半双工，插话靠耳机。）

**外放"说话即打断"（真 barge）只有两条路**：
1. **戴耳机** + 免手面板开「声控插话」——耳机下麦听不到扬声器，自适应双讲检测成立。
2. **远程 TTS**（吐 PCM）：由本模块**自渲染成通话音频**（`STREAM_USAGE_VOICE_COMMUNICATION`）+
   强制扬声器 → 与 `SOURCE_TYPE_VOICE_COMMUNICATION` 采集配对 → **硬件 AEC 消掉 TTS** → 外放也能声控打断。
   实现已就位（`AudioPlayer.setCallAudio` + `VoiceSession.aecCapable`），配好远程 TTS 端点即自动启用。

## 5. 离线 TTS 为何是"实验"

端上神经 TTS（MeloTTS）在手机上**慢于实时**（句间停顿明显），且**无可用 NPU 通道**——
sherpa 的 onnxruntime 只有 CPU/XNNPACK，鸿蒙 NPU（MindSpore Lite / NNRt / HiAI）要转 `.ms`/`.om`
并重写整条 TTS 管线（数周、TTS 算子 NPU 支持差常回落 CPU，ROI 低）。**本机"已上 NPU 的 TTS"就是系统 TTS 本身。**

故：
- **朗读默认走系统 TTS**（快）；离线 MeloTTS 降为设置里的实验开关（默认关）。
- **电话模式不用离线 TTS**：其异步合成器在电话的"快速合成 + 打断"循环里会 native use-after-free 崩溃
  （已定位、已隔离）。电话模式只走系统（半双工）/远程（barge）。
- 离线 **识别**（SenseVoice）稳定可用，保留。

## 6. 配置远程语音（推荐用于外放 barge + 好音质）

**LM Studio 不行**（只服务 LLM，无音频端点）。用 OpenAI 兼容的本地服务：
- **一体**：LocalAI（LLM + Whisper ASR + TTS）
- **专用**：TTS 用 **openedai-speech** / Kokoro-FastAPI；ASR 用 **speaches**（faster-whisper-server）

**接入**（设置 → 远程语音服务，字段即 OpenAI 兼容，填基址 `…/v1` 或完整 URL 均可）：
- ASR：形式 `openai`；地址 `http://<PC局域网IP>:<端口>/v1`；模型如 `whisper-1`
- TTS：地址同上；模型如 `tts-1`；音色如 `alloy`；**响应必须 wav**（本模块只解 wav）
- Key：本地服务无鉴权则留空
- ⚠️ **明文 HTTP**：到「设置 → 网络策略」把该 IP 加进抓取白名单；确保 pad/PC 同一 Wi-Fi、用局域网 IP

配好远程 TTS 后，电话模式外放即启用回声消除、可声控打断（面板显示「回声消除已启用」）。

## 7. 离线模型下载

设置页：
- 「离线语音识别」：下载 SenseVoice（~230MB，默认源 hf-mirror，可改）+ 「优先使用离线识别」开关
- 「离线朗读 TTS（实验）」：下载 MeloTTS（~66MB）+ 「用离线朗读（实验·较慢）」开关

权重不随应用打包，运行时下到沙箱 `filesDir/sherpa-asr`、`filesDir/sherpa-tts`。

## 8. 架构（`common/core-speech` HAR）

```
SpeechService（门面：能力检测 + 分层降级 pickAsr/pickTts；上层只调 startDictation/readAloud）
  ├─ asr/  SystemAsrEngine · RemoteAsrEngine(openai) · FunAsrWsEngine(ws) · SherpaAsrEngine(+能量VAD)
  ├─ tts/  SystemTtsEngine · RemoteTtsEngine(/audio/speech→wav) · SherpaTtsEngine(MeloTTS,串行化)
  ├─ audio/ AudioCapture(16k/mono/PCM16) · AudioPlayer(通话音频渲染+扬声器) · WavCodec
  ├─ VoiceSession（电话模式状态机：listening→thinking→speaking 连续多轮 + 半双工回声护栏 + barge）
  └─ BargeInDetector（自适应双讲检测，耳机/远程 AEC 场景）
上层：features/chat（按住说话 / 朗读 / VoiceCallPanel 音波 UI）、features/settings（配置与下载）
```

契约要点：引擎回调用**函数属性**式（ArkTS 对象字面量不能实现方法签名接口）；`AsrOptions.echoCancel`、
`TtsOptions.callAudio` 贯穿通话音频与 AEC。

## 9. 已知限制

- **外放声控打断需远程 TTS 或耳机**（系统 TTS 消不了回声，见 §4）。
- **离线 TTS 慢**、不用于电话模式（见 §5）；离线识别为非流式（说完才出字）。
- 端上神经推理（TTS/LLM）**不走 NPU**（框架/算子限制），CPU 上跑；重推理留给 PC。
- VAD 为能量端点，阈值可能需按机型麦增益微调；标点准确度有限（可接 sherpa OfflinePunctuation，待办）。
- 端到端语音需真机人工测（麦/听声不可自动化）；设备锁屏常挡自动化。
