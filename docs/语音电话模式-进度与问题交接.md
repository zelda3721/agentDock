## 3. 核心未解决问题：外放声学回声（重点读这节）

### 症状（真机反复出现）
外放（不戴耳机）时：助手朗读答案 → **麦克风把助手自己的 TTS 收进去** → ASR 识别成"用户说的话" →
发给 LLM → 助手回应自己刚说的 → **自问自答、对话顺序错乱**。声控插话也因此**误触发/失灵**。

### 根因链（已定论）
1. **能量 VAD / Silero VAD 都区分不了"用户人声"和"TTS 人声"**——TTS 输出本身就是语音，麦一收到就当用户说话。
2. 唯一出路是**声学回声消除（AEC）**。AEC 的前提是拿到**参考信号**（"正在播的是什么"）从麦信号里减掉。
3. **系统 TTS（Core Speech Kit）是黑盒**：
   - **不吐 PCM** 给我们（`engine.speak()` 直接自己播）；
   - 用普通媒体音频路径播、**不在通话（VOICE_COMMUNICATION）音频路径**里。
   - → 软件 AEC 没参考信号；硬件 AEC（`SOURCE_TYPE_VOICE_COMMUNICATION` 采集）也拿不到它当参考。
   - **真机实测：加了硬件 AEC 采集，系统 TTS 外放回声仍消不掉**（用户仍"TTS 被识别"）。

### 参考项目怎么做的（已核对源码）
`huggingface/speech-to-speech`，`VAD/vad_handler.py`：
```python
if not self.should_listen.is_set():
    return                 # 助手应答期间不把麦喂给 STT
...
self.should_listen.clear() # 开始应答时清掉 → 半双工
```
**它就是半双工（说话中停止听），不做 AEC。它的"插话"依赖用户戴耳机**（麦听不到扬声器）。

### 结论
- **外放 + 系统 TTS = 做不了真声控插话**（回声原料都拿不到）。
- 半双工（说话中不开麦，播完再听）是外放场景的正确默认，且仍是**全程免手连续多轮**。

## 4. 当前设计（commit `56cfc5a` 后的状态）

`common/core-speech/src/main/ets/VoiceSession.ets` 是电话模式内核：

- **默认严格半双工**：`speaking` 态**完全不开麦**（`bargeEnabled` 默认 false，不启 BargeInDetector）。
  一轮朗读播完 → `scheduleListenAfterEcho()` 切 UI 到聆听 + 停插话采集 + **等 `ECHO_GUARD_MS=400ms`**
  让扬声器尾音衰减 → 再真开麦。→ 杜绝把自己朗读收进识别。
- **连续多轮**：`maybeFinishTurn()` 一轮讲完自动回聆听，循环到用户挂断（`state==='speaking'` 守卫防二次开麦）。
- **识别麦加 AEC**：`AsrOptions.echoCancel`，VoiceSession 全程 `echoCancel:true` →
  SherpaAsrEngine 用 `SOURCE_TYPE_VOICE_COMMUNICATION`（**仅 sherpa 生效**，系统档 ASR 用内建麦不可指定）。
- **声控插话 = 显式开关**（`VoiceSession.setBargeEnabled`；面板 Toggle「声控插话（戴耳机时开）」，**默认关**）：
  仅戴耳机时开。开则 `speaking` 态并行 BargeInDetector（自适应双讲检测：跟踪回声残留底噪 EMA，
  帧能量持续 `BARGE_MIN_MS=360ms` 高于底噪 `TRIGGER_FACTOR=2.2×` 才判插话）。
- **外放打断兜底**：面板「打断说话」按钮 → `interrupt()` → `doInterrupt()`（停播 + 取消生成 +
  **await barge 采集释放再开 ASR**，避免两路抢麦致识别启动失败）。
- **屏上诊断读数**：`speaking` 态显示 `回声残留 floor / 麦 rms`（`onVadDebug` 回调），rms>floor×2 转绿。
  仅声控插话开时有意义。（因 hilog 在本机静默，诊断改屏上——见 §7）

**待用户测**：① 外放、开关关：连续多轮**是否不再自问自答**（最要紧）；② 戴耳机、开开关：声控插话是否灵。

## 5. 下一步：外放也要真·免手插话（换非系统 TTS）

用户已问「换非系统 TTS 就能借鉴（ChatGPT/Claude 外放免手）吗」——**能**。ChatGPT/Claude 外放免手靠 AEC，
关键是**它们自己渲染 TTS、手里有参考信号**。我们**远程 `/audio/speech` 已能拿到 PCM 自渲染**（`RemoteTtsEngine`
+ `AudioPlayer`），所以路子通：

**方案（当 TTS 是远程/离线 PCM 档时启用外放声控插话）：**
1. `AudioPlayer` 渲染 TTS PCM 时，流用途从 `STREAM_USAGE_VOICE_ASSISTANT` 改 **`STREAM_USAGE_VOICE_COMMUNICATION`**（通话音频）。
2. **强制走扬声器**（`audio.AudioManager` 开 speakerphone / setCommunicationDevice，避免通话默认走听筒）。
3. 采集端保持 `SOURCE_TYPE_VOICE_COMMUNICATION`。
4. → 播放+采集同进通话音频路径，**硬件 AEC 拿到参考消掉 TTS** → 外放真·免手插话。
5. 硬件 AEC 若仍不够干净 → 上**软件 AEC（移植 WebRTC AEC3）**：拿 (麦帧, 参考帧) 自己消，跟设备无关（工程量大）。

**前提**：需要一个**吐 PCM 的 TTS 端点**（自建 openedai-speech / TTS 服务），不能用系统 TTS。
顺带解决系统 TTS 机械感。**系统 TTS 档仍走半双工**，UI 据档位自适应文案，不谎报能力。

**落地建议**：先接 §5.1~5.3（通话渲染+强扬声器+AEC 采集），电话模式里**远程 PCM TTS 档自动允许外放声控插话**，
用屏上 floor/rms 读数量回声残留；消不干净再评估 AEC3。

## 7. 环境坑 & 命令（换机务必看）

**换机需重建的本地资源（不在 git 里）：**
- **`build-profile.json5` 含本地签名材料，绝不入 git**（pre-commit `tools/git/sanitize-signing.mjs` 会剥成
  `signingConfigs: []`）。新机需在 DevEco 里重新配置调试签名。当前工作树 `build-profile.json5` 有本地改动（签名），**别提交**。
- **`third_party/sherpa_onnx-1.10.32.har` 是 gitignored**（预编译 arm64）。新机跑 `tools/speech/fetch-sherpa-onnx.sh` 重新拉。
  （`products/default/entry/oh-package-lock.json5` 的改动来自该本地 .har 依赖。）
- 离线 ASR 模型（~230MB）下载在设备 `filesDir/sherpa-asr`，不在仓库；新机不影响，设备端已有则仍在。

**密钥红线：** API Key/密钥只进 SecretStore，绝不进 kv_config/RDB/日志。
**kv_config 键名不能含** `token/secret/key/password/apikey/credential` 片段（密钥卫士会拒），已踩过（`voice.sherpa_vocab_url`）。
